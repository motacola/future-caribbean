## 3. Unclear or could be misread

**a. `optional-synthesis` is a floating node with zero connections.**
It appears in `components` but in no entry of `connections` in
`signal-fabric-system-map.compact.architecture.json`. A reader sees a box with
no inputs or outputs and concludes synthesis is a side experiment. It is not:
`run_pipeline.sh:119` runs it inside the same range the map cites as
"essential transformations" (89-147); `outbox/reasoning.json` is a committed
artifact, a deployed Vercel function (`api/reasoning.py`), a listed HTTP tool
(`api_manifest.py:94-97`), an MCP/CLI surface (`cli/signalctl.py:221`), and is
fetched at runtime by the public homepage (`src/pages/index.astro:2978`).

The *prose* is careful and truthful — "Optional synthesis may exist in the
pipeline, but the public `/api/ask` path is deterministic". The *diagram* is
not: it shows the seam without showing that model-or-fallback output reaches
the public artifact layer and the public site.

**b. The delta gate covers one file.** `TRACKED_FILES = ["telegram_brief.md"]`
(`distributors/delta_outbox.py:26-28`). The operations diagram's
`artifact-build -> delta-gate` edge reads as if the whole artifact build passes
through content-hash idempotency. Add "telegram brief" to the label or the edge.

**c. Approval sublabel is a partial enum.** "Pending · approved · sent" omits
`dry-run-sent` and `rejected`, both real (`.flue/tools/delivery.ts:20`).

**d. Two out-of-range citations in `signal-fabric-system-map.md`:**
`.github/workflows/pipeline.yml:28-100` (file is 97 lines) and
`vercel.json:1-106` (file is 76 lines).

**e. Test caveat.** `test_token_validation_uses_constant_time_comparison`
monkeypatches `hmac.compare_digest` to return True and asserts the call args.
It proves the call site, not that comparison is constant-time in all paths.
Fine, but do not cite it as proof of timing-attack resistance.

## 4. Missing

**a. `verification` is drawn in a release path nothing invokes.**
`scripts/verify.sh` has **no automated caller**: `grep -rn "verify.sh"` matches
only the diagram JSON/HTML, `scripts/README.md`, and a comment in
`scripts/shot.mjs`. `.github/workflows/pipeline.yml` runs `run_pipeline.sh` and
then commits — it never runs the gate. The `verification -> artifact-commit`
edge therefore misrepresents the scheduled release path. Compounding this, the
`publication-blocked` node cites `run_pipeline.sh:174-183`, which is the
*essential-step* fail-closed — a different mechanism than the verify gate the
node is named for. Two mechanisms are collapsed into one node.

**b. The shipped main HTML is a version behind its own source.** Extracting
`archify-source-evidence-data` from `signal-fabric-system-map.html`: 10 nodes,
`referenceCount: 25`. The JSON has 11 nodes and 27 references. Rendered labels
are "Deterministic signal pipeline" and "Ranking and packaging", not
"Deterministic core" and "Resolvers + packaging"; "synthesis" does not appear
in the file at all. mtimes corroborate — HTML 11:46, JSON 12:59, companions
13:57. The handover's description of the main map describes the JSON, not the
artifact anyone will open.

**c. The `.md` never mentions `reasoners/`.** Steps 1-8 of "End-to-end flow"
skip it and the "Primary code evidence" table has no row for
`reasoners/synthesis.py` or `/api/reasoning`, despite the Trust-model bullet.

**d. Unauthenticated GET disclosure is undescribed.** Writes are locked, but
`/api/delivery/approvals` and `/api/webhooks` are readable over GET with
`Access-Control-Allow-Origin: *` (`server.py:130-158`, `_cors` at `:253-256`),
so any page the operator visits can read the pending-approval queue and the
webhook subscriber list. No `Host` header check, so loopback binding alone does
not stop DNS rebinding. Subscriptions carry no secret (`webhook_notifier.py:43`
uses `secrets.token_hex` only for the id), so this is disclosure, not
credential leak — but "read paths are the default public surface" should say so
explicitly for a *local operator* server rather than leaving it implied.

## 5. Highest-value edits

1. **Re-render `signal-fabric-system-map.html` from the current JSON, and wire
   `optional-synthesis` into the graph** — at minimum
   `optional-synthesis -> artifact-layer` labelled "labelled engine · reasoning.json",

2. **Split or relabel the `verification` node in the operations diagram.** Either

   `.github/workflows/pipeline.yml` between the pipeline run and the commit so
   the diagram becomes true. The second is the better fix — the diagram is
   describing the system you want.

**Correction to this document.** Above I wrote "eight legal transitions".
`LIFECYCLE_TRANSITIONS` has three source states with three targets each, so it is
**nine**. The diagram and its cards say nine.

It draws all six states (`proposed`, `evidence_requested`, `evidence_received`,
`verified`, `rejected`, `expired`) and all nine legal moves. Three of those states
and the whole transition structure appeared nowhere in the previous package.

**A tradeoff worth knowing:** `lifecycle` mode has no `meta.repository` and no
per-state `sources` — repository evidence is architecture-only (`--repo-root` is
documented as "architecture only"). So this diagram cannot carry verified,
revision-pinned citation links the way the other three do. Its citations live in
the cards as `interventions.py:<lines>` text and are correct against `2cfa9d1`,
but they are not machine-verified by Archify. That is a real reduction in
evidence strength and is the price of showing the state machine at all.

Sublabels were dropped: with four main columns plus three terminal columns, no
sublabel row clears the 6px readability floor at 1440px. The labels are the
literal status strings from the code, which is the load-bearing content.

**The reservation:** six exit edges converge on two terminal states, and in the
static overview you cannot trace which active state each dashed path leaves. Only
the arrowheads at the terminals are individually legible. This is topological, not
a tuning failure — placement sweeps over every terminal column combination all
returned the same crossing count, and the fan only became clean by sending
rejection through bottom corridors and expiry over the top, which is what produces
the large dashed rectangles.

The three guided views ("Evidence path", "Rejection and expiry", "Verification
guards") isolate each concern and are the intended way to read it. The alternative
— drawing fewer exit edges — would under-draw the transition table, which is the
exact criticism this diagram exists to answer. I chose completeness over a
cleaner static first impression; that is a judgment call and it is reversible.
